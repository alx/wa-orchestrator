wa-orchestrator 1 process · N groups

One WhatsApp account, registered groups, and a brain per group: a pi 1.2.0 agent run inside a sandboxed Docker container, with a locked LLM model.

Architecture

WhatsApp ──wwebjs──▶ index.js ──per group──▶ brain.js ──docker──▶ container (1 account) registry docker run pi agent ├─ beads (read-only) ├─ tools (git, hugo…) └─ 1 brain ≠ 1 group

The brain is chosen per group (the brain field of the registry), not per message nor per server. Two profiles ship by default:

profilefree-text pi …run modes
beads-projectproject beads (list/create by label)pi run <bead> → executes the bead, artifacts on branch task/<id>
site-projectscoped read-only beads (live Dolt DB, filtered to a set of epics)pi edit <instruction> → edits the site, verifies the build, commit + push

Quickstart

npm install
bash sandbox/build.sh          # docker image (pi, bd, jq, hugo_extended)
cp config.template.json config.json   # fill JIDs + absolute paths
cp brain-prompts.template.json brain-prompts.json   # adapt prompts
# user-scoped systemd units provided (fill <HOME>/<NODE_BIN>):
systemctl --user enable --now wa-orchestrator wa-orchestrator-dashboard

Prereqs: docker, xvfb-run, system Chromium, node ≥ 22. The WhatsApp session lives in sessions/ — one client per account, never two instances at once. Prompts load from brain-prompts.json (gitignored); without it the bot falls back to minimal generic built-in prompts.

Extending

  • Add a group = one entry {"jid", "name", "brain"} in groups[] + a restart. JID: first message from the group, or xvfb-run -a node discover.js during a maintenance window.
  • Add a brain = one profile in brains{} (beads repo, prompt entries, run modes) pointed at by the registry.

Security

  • Every member of a registered group can command the bot (no per-member auth).
  • Write-capable run modes are scoped in the prompt: minimal edits, build before push, never force-push, never .github/.
  • Credentials are materialized inside the container, never in the repo (config.json and brain-prompts.json gitignored; only templates are published).
  • Everything is traced: activity/activity.jsonl + dashboard :8093.

Pi package / npm

Distributed as a pi package (keyword pi-package, manifest pi): pi install npm:wa-orchestrator installs the daemon and the operations skill.

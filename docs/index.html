wa-orchestrator 1 processus · N groupes

Un compte WhatsApp, des groupes enregistrés, et un cerveau par groupe : agent pi 1.2.0 exécuté dans un conteneur Docker sandboxé, modèle LLM verrouillé.

Architecture

WhatsApp ──wwebjs──▶ index.js ──par groupe──▶ brain.js ──docker──▶ conteneur (1 compte) registre docker run agent pi ├─ beads (lecture seule) ├─ outils (git, hugo…) └─ 1 cerveau ≠ 1 groupe

Le cerveau est choisi par groupe (champ brain du registre), pas par message ni par serveur. Deux profils livrés :

profilfree-text pi …run modes
ai-slopbeads du projet AI Sloppi run <bead> → artefacts sur branche task/<id>
cpobeads du Centre de la Photographie Ordinairepi edit <instruction> → édite le site, build Hugo, commit + push

Démarrage rapide

npm install
bash sandbox/build.sh          # image docker (pi, bd, jq, hugo_extended)
cp config.template.json config.json   # remplir JIDs + chemins
# unités systemd user-scoped fournies :
systemctl --user enable --now wa-orchestrator wa-orchestrator-dashboard

Prérequis : docker, xvfb-run, Chromium système, node ≥ 22. La session WhatsApp vit dans sessions/ — un seul client par compte, jamais deux instances en même temps.

Extension

  • Ajouter un groupe = une entrée {"jid", "name", "brain"} dans groups[] + redémarrage. JID : premier message du groupe, ou xvfb-run -a node discover.js en fenêtre de maintenance.
  • Ajouter un cerveau = un profil dans brains{} (dossier beads, prompt, run modes) pointé depuis le registre.

Sécurité

  • Tous les membres d'un groupe enregistré peuvent commander (pas d'auth par membre).
  • Run modes d'écriture scopés par prompt : édits minimaux, build avant push, jamais de force-push, jamais .github/.
  • Credentials matérialisées dans le conteneur, jamais dans le repo (config.json gitignored, seuls des templates sont publiés).
  • Tout est tracé : activity/activity.jsonl + dashboard :8093.

Paquet pi / npm
